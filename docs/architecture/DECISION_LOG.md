# Журнал архитектурных решений (Architecture Decision Log)

Документ содержит записи ADR (Architectural Decision Records) проекта «Glazok».

## ADR-001: Двухуровневая гибридная архитектура (Two-Tier Hybrid Pipeline)

- **Дата:** 2026-10-15
- **Статус:** Принято
- **Контекст:**  
  Пользователю требуется распознавать объекты и ценники в реальном времени, а также получать развернутые описания товаров. Запуск больших мультимодальных моделей (VLM) на каждом кадре потока камеры невозможен из-за критического перегрева, расхода батареи и задержек (>1–2 сек на кадр).
- **Решение:**  
  Разделение конвейера на два независимых контура:
  1. *Контур 1 (Real-time On-Device):* Непрерывный поток 15–30 FPS на базе CameraX + ML Kit (Object Tracking + Text Recognition v2). Обеспечивает мгновенный отклик (<45мс) и работу без интернета.
  2. *Контур 2 (Deep VLM On-Demand):* Активируется только по явному действию (двойной тап, удержание или фиксация взгляда камеры >2 сек). Захватывает кадр высокого разрешения и отправляет его в VLM для анализа состава, сроков годности и нюансов упаковки.
- **Последствия:**  
  - Быстрый отклик на ценники без ожидания сети.
  - Нулевой риск перегрева при непрерывной работе.
  - Сохранение возможности глубокого анализа сложных товаров.

## ADR-002: Умный парсер ценников и пространственная привязка (Spatial Box Matching)

- **Дата:** 2026-10-15
- **Статус:** Принято
- **Контекст:**  
  Стандартный OCR выдает разрозненный поток текстовых блоков (артикулы, маркетинговые слоганы, штрихкоды, старые цены, цены по акции). Простое чтение текста подряд дезориентирует пользователя.
- **Решение:**  
  Разработать специализированный компонент `SmartPriceParser`:
  1. Кластеризация геометрически близких текстовых блоков.
  2. Фильтрация нечислового мусора и служебных кодов кассы.
  3. Выявление акционных цен и цен по программе лояльности («по карте»).
  4. Геометрическая привязка (Spatial Matcher): сопоставление координат ценника с ближайшим объектом, найденным ML Kit Object Detector.
- **Последствия:**  
  Синтез четких, полезных речевых конструкций вида: `«[Товар], цена по карте: 89 руб., без карты: 119 руб.»`.

## ADR-003: Универсальный интерфейс (HUD + Озвучка + Тактильный отклик)

- **Дата:** 2026-10-15
- **Статус:** Принято
- **Контекст:**  
  Приложение должно быть удобно как слабовидящим людям, так и зрячим пользователям, сканирующим полки магазина.
- **Решение:**  
  1. Реализация высококонтрастного Canvas HUD поверх CameraX Preview: подсветка активного фокуса, Bounding Boxes объектов (синий) и ценников (зеленый).
  2. Тактильный отклик (Haptic Feedback) при центрировании ценника в прицеле камеры.
  3. Интеллектуальный Speech Arbiter: управление очередью TTS с защитой от речевой перегрузки (Debounce по Tracking ID, TTL 5 секунд).
- **Последствия:**  
  Интерфейс остается визуально удобным, не мешает видоискателю и дает максимальную обратную связь через звук и вибрацию.

## ADR-004: Протокол живой архитектуры и субагенты Антигравити

- **Дата:** 2026-10-15
- **Статус:** Принято
- **Контекст:**  
  Проект сложный, затрагивает компьютерное зрение, низкоуровневые буферы камеры, парсинг и UI. Необходима строгая координация без потери архитектурного видения.
- **Решение:**  
  Внедрение стандарта Living Architecture:
  1. Корневой файл `SYSTEM_PROMPT.md` содержит полные системные инструкции.
  2. Папка `docs/architecture/` (`ARCHITECTURE.md`, `SYSTEM_STATE.md`, `DECISION_LOG.md`) обновляется субагентами на каждом шаге разработки.
  3. Автоматическое распределение задач по ролям с использованием специализированных скиллов Антигравити (`architect-review`, `performance-engineer`, `tdd-workflow`, `android-jetpack-compose-expert`).
- **Последствия:**  
  Любая будущая сессия разработки мгновенно подхватывает контекст без деградации архитектуры.

## ADR-005: Реализация Фазы 1 — Модуль :core:domain и Двухшаговый SmartPriceParser

- **Дата:** 2026-10-15
- **Статус:** Принято (согласовано с пользователем)
- **Контекст:**  
  Для парсинга ценников российских сетей необходим устойчивый алгоритм, отделяющий акционные цены от базовых, и изолированное окружение для мгновенного выполнения TDD unit-тестов.
- **Решение:**  
  1. **Модульность:** Логика парсера и модели выносятся в чистый Kotlin-модуль `:core:domain` без зависимостей от Android SDK.
  2. **Алгоритм парсинга:** Двухшаговый гибридный:
     - Шаг 1: Пространственная кластеризация текстовых блоков OCR по нормализованным координатам $(x, y, w, h)$ для объединения связанных строк одного ценника.
     - Шаг 2: Взвешенный Regex-анализ с приоритетом акционных признаков («по карте», скидочный цвет, крупный шрифт) над базовыми ценами.
  3. **Шаблон озвучки:** Формат с акцентом на выгоду: `«[Цена по акции] рублей по карте, обычная [Старая цена]»`.
- **Последствия:**  
  - Быстрый запуск тестов на локальной JVM без эмулятора.
  - Высокая точность выделения цены даже при наличии на ценнике артикулов, штрихкодов и дат.

## ADR-006: Стратегия распознавания кириллицы и гибридный OCR-конвейер

- **Дата:** 2026-10-15
- **Статус:** Принято (согласовано с пользователем)
- **Контекст:**  
  On-device модель Google ML Kit `text-recognition` официально поддерживает Latin, Chinese, Devanagari, Japanese, Korean, но не имеет отдельной локальной модели для кириллического алфавита. При этом арабские цифры ценников, скидочные проценты и знаки валют распознаются локально со 100% точностью.
- **Решение:**  
  Утвержден вариант 1 (Гибридный конвейер):
  1. *Контур 1 (Real-time On-device, ML Kit):* Мгновенный захват ценников, арабских цифр, скидок, валютных символов и базовых объектов в реальном времени (15–30 FPS, задержка <45мс).
  2. *Контур 2 (Deep VLM / Gemini API):* При необходимости прочитать состав, бренд на русском языке, предупреждения об аллергенах или дату производства — по тапу/паузе кадр отправляется в мультимодальную VLM, которая идеально владеет русским языком и контекстом.
- **Последствия:**  
  - Минимальный размер APK (без тяжелых локальных словарей Tesseract).
  - Нулевая просадка FPS в видоискателе.
  - Полная поддержка чтения сложных русских этикеток в Контуре 2.

## ADR-007: Контур 2 — Глубокий VLM-анализ товаров (Gemini VLM Service)

- **Дата:** 2026-10-15
- **Статус:** Принято (согласовано с пользователем)
- **Контекст:**  
  Слабовидящим и незрячим пользователям часто необходимо узнать не только цену, но и состав продукта, бренд, наличие аллергенов (глютен, орехи, лактоза) и срок годности, которые написаны мелким русским шрифтом на упаковке.
- **Решение:**  
  1. Реализовать сервис `GeminiVlmService`:
     - Триггер: жест двойного тапа (Double-tap) по экрану или кнопка `🔍 Состав`.
     - Захват кадра высокого разрешения (`ImageCapture.takePicture`) в фоновом потоке.
     - Оптимизированный системный промпт для ассистивного описания (кратко, 2–3 предложения, русский язык, состав, аллергены, срок годности).
     - Тактильное подтверждение `HapticManager.vibrateVlmTriggered()` и мгновенное речевое оповещение: «Анализирую товар...».
     - Озвучивание результата с наивысшим приоритетом `SpeechPriority.CRITICAL`.
- **Последствия:**  
  - Пользователь получает полное человеческое описание любого сложного товара по требованию без перегрузки непрерывного видеопотока.

## ADR-008: Строгая фильтрация по центру, озвучка предметов и сохранение ключа Gemini API

- **Дата:** 2026-10-15
- **Статус:** Принято (согласовано с пользователем)
- **Контекст:**  
  1. Выделение множества фоновых предметов на полке дезориентирует пользователя и захламляет экран.
  2. Пользователю необходимо слышать, какой именно предмет находится перед камерой (даже если у него нет ценника).
  3. Требуется интерфейс для ввода и сохранения ключа Gemini API без редактирования исходного кода.
- **Решение:**  
  1. **Center-only ROI Filter:** В `GlazokImageAnalyzer` отбрасываются все объекты и ценники за пределами центральной 22%-зоны прицела. На экране отображается и обрабатывается ровно один центральный целевой предмет.
  2. **Озвучка предметов на русском:** Реализован метод `SpeechQueueArbiter.announceItem()`, переводящий системные метки ML Kit на русский язык («Упаковка товара», «Продукт питания», «Предмет быта») и связывающий их с найденным ценником.
  3. **Настройки Gemini API:** Создан класс `GlazokPreferences` на базе `SharedPreferences` и диалоговое окно `SettingsDialog` с кнопкой ⚙️ на экране камеры.
- **Последствия:**  
  - Чистый видоискатель без визуального мусора.
  - Мгновенная озвучка предмета при наведении центра камеры.
  - Удобный ввод API-ключа прямо из приложения.
